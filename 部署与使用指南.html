部署与使用指南

把会员订阅、年费、水电燃气、API 按量消费和收入记在一处，自动算出每月固定支出、年化支出，以及每笔订阅本期的「剩余价值」。纯 Python 标准库后端 + 单文件前端，一条命令部署到 Debian 13。

Debian 13systemd 开机自启SQLite 存储公网 :21117可选访问令牌

五步部署

目标：浏览器打开 http://服务器公网IP:21117 即可使用。

上传并解压

把 account-hub.tar.gz 传到服务器（scp / 面板上传均可），解压得到 account-hub/ 目录。

scp account-hub.tar.gz user@服务器IP:/tmp/
ssh user@服务器IP
cd /tmp && tar -xzf account-hub.tar.gz

一键安装

脚本会复制文件到 /opt/account-hub，写入 systemd 服务并立即启动、设置开机自启。Debian 13 自带 python3，无需装任何依赖。

cd account-hub && sudo bash install.sh

放行 21117 端口

系统防火墙和云厂商安全组都要放行 TCP 21117。

sudo ufw allow 21117/tcp   # 未启用 ufw 可跳过
公网打不开的第一大原因：云控制台的「安全组 / 防火墙规则」没放行 21117。先在服务器本机 curl http://127.0.0.1:21117/api/health 确认服务正常，再去云控制台加规则。

浏览器访问

打开 http://<公网IP>:21117。首次是空账本：点「载入示例数据」先看效果，之后删掉示例换成自己的项目。

开启访问令牌（推荐）

服务暴露在公网上，建议加一层口令。令牌存在浏览器里，换设备输入一次即可。

echo '你的口令' | sudo tee /opt/account-hub/token.txt

它帮你管什么

页面从上到下：关键指标 → 即将续费 → 分类占比 → 订阅剩余价值 → 全部项目（增删改查）。

关键指标

本月固定支出、月均收入、每月结余（含年结余预估）、年化支出、在管项目数。

即将续费

未来 30 天内要扣费的项目，按紧急度标注「今天 / 明天 / N 天后」。

分类占比

月均支出按 16 类支出分类的环形图与排行，一眼看出钱花在哪。

剩余价值

每个订阅本期「已用 / 剩余」进度条、剩余价值、日均成本、下次扣费日。

数据备份

一键导出 JSON；换服务器用「导入」整体迁移；也可直接拷贝 SQLite 文件。

访问令牌

token.txt 放进安装目录即启用，删除即关闭，实时生效不用重启。

「剩余价值」怎么算

订阅是预付费：先付钱、后享受。剩余价值回答的是"这个月/这一年，我还剩多少服务没用完"。

剩余价值 = 每期金额 × 本期剩余天数 ÷ 本期总天数

本期以「开始日期 + 周期循环」推算：月付按扣费日循环（31 号这类日期在 2 月自动钳制到月末）；年付按开始日期周年循环。日均成本 = 每期金额 ÷ 本期总天数。例：月付 30 元、本月已过 20 天 → 已用 20 元、剩余 10 元、日均 1 元。年付健身房 2380 元用了 150 天 → 剩余价值 ≈ 1403 元，这就是"退卡大概能退多少"的参考。
